## 独立复算结果

详见 `independent_analysis.json` 和可执行脚本 `independent_analysis.py`。

- R1 candidate vs dedup+TTL：交付 -8.77598%；逻辑操作 +14.99254%；计量字节 +19.99369%。
- R2：480 次规则重建；80 对 candidate/FIFO 派发序列一致。32 个瓶颈评估世界有 438 个压力 tick；candidate 平均多做 59.46875 次压力检查，却不改变派发。
- R4：6,268/7,085 = 88.4686% 已执行公共校验的动作被拒绝；2,970,028/3,402,842 = 87.2808% tokens 位于这些动作；3,030,343/3,402,842 = 89.0533% 为提示 tokens。
- R4：173/398 = 43.4673% 已发布有效检查重复原来源；这是检查来源重复比例，不是独立证据比例或全部工具调用比例。
- R4：mixed 的小模型占 413,350/(413,350+65,612) = 86.3012% tokens。首次成功出现在中模型槽位，不等于中模型单独造成全部成功。
- R4：versioned 相比 dedup+TTL，在报告的每四世界 fixed-call condition 中 token 减少 1.6314%、逻辑操作减少 0.4706%，最终质量没有变化。该差值不可当成已证明的总体优势。
- R4：最终版本占 16 个全局轮次。private 在 N>=8 时任一 agent 至多获得 2 次最终版本行动，少于“三次检查 + 一次提交”的最低 4 次。该条件下失败有设计上的可达性限制。

## 结论层次

1. 工程：有限、可信单宿主 Session 原型有实质进展。
2. 测量：身份固定、失败保留、未知费用、版本化 reanalysis 的做法值得保留。
3. 效能：当前没有建立群体策略的普遍收益；R1/R2 特定实现增加开销。
4. R3 有一个世界上的共享回执正面诊断线索，但不是跨任务末端成功率提升。
5. 原始愿景中的动态目标分解、真实局部自主组织、自适应招募/升级与长期运行仍未由当前有限 DAG/串行 round-robin 实验验证。

## 下一轮建议（提案，不是历史门槛修改）

### P0：新版本动作接口与任务可达性诊断

冻结现有证据。把输出格式、合法工具目标、证据覆盖、推理整合、提交与隐藏评估分别计量。合法动作目标使用公开索引/枚举，不让 `index_entry` 占位符成为可执行目标；约束解码或工具 schema 必须同等应用于所有方法。新增“给齐当前证据且只允许 submit”“自动收集 + 自由选择”“完全自主”三个诊断层，不把前两者包装成协调收益。

### P1：区分证据存储、注意力、错误反馈

当前有效证据应按 `(scope, source_id, source_version)` 可查询；TTL 用于注意力，而不是让仍有效的必要证据仅因离开四条窗口就不可访问。错误反馈不获得事实权限，也不应无限挤占关键证据。通过来源任务租约与版本感知缓存减少重复检查，所有读取、刷新和计算成本继续计量。

### P2：先用 2–4 个 agent 建立真正的协作因果对照

候选策略必须改变实际工作选择或信息组合，而不只是改变轮次所有者。比较共享正确回执、等长无关回执与不共享；执行完整后续 rollout。使用新的构造/抽样世界，保留单体、强简单 blackboard 与 manager 对照。全共享、同模型、同 seed 的 N 重标记实验只作为 expected-null 控制，不作为主要规模收益证据。

### P3：独立补运行成熟度

真实并发竞争、时钟/挂起恢复、模型异常、日志增长、清理策略、受限端到端恢复与长运行测试单独版本化。不要把 finite safe disposition 当作 universal recovery。原子权限提交边界不得为降低开销而放松。

### P4：收敛交付面

选定一个新的不可混淆实验版本与安装组合，保留旧 `0.1.0.dev1` cohort 的原始包。为安装了 Session 的完整集成测试单独设置任务；17 个 absent-Session skips 不算通过。完整 core suite 尚未完成时不宣布完整回归通过。无需继续新增无具体调用者的 Governance 对象。
