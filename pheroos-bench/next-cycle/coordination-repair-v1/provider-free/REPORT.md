# Installed Session provider-free instrument

Configuration `coordination_repair_provider_free_campaign_v1` ran once against
installed runtime `0.1.0.dev2`. Exact runner, source hashes, Python identity and
fixed world/arm lists are in `config.json`. Sources remained unchanged throughout
collection. This was scripted public-tool reference execution; no model was
loaded or dispatched and no confirmatory evidence was collected.

All **61 episodes were VALID_KNOWN and successful**: eight development worlds
under each of D0, D1 and D2 (24), four pilot worlds under seven declared arms
(28), and nine complete downstream fork branches. No failed or invalid episode
was removed. Preparation, validation, source inspection, current authorization
and retrieval crossed the same installed Session facilities and accounting.
The 184.66-second campaign proves these finite public-tool conditions are
reachable; it establishes neither learned actionability nor coordination efficacy.

The fixed candidate-N2 prefix was eligible in three worlds. Relevant, withheld
and irrelevant branches all completed under their remaining action/token bounds.
The version-correction prefix was ineligible because its retained version-1
receipt was historical at the child's declared next step; the explicit reason
and excluded references are preserved. Branch setup reissued tool artifacts
under fresh child authority. Parent costs and branch increments remain separate.

`summary.json` retains the initially broad behavioral comparison, which counted
agent labels and suggestions and found seven changes among eight comparisons.
**The narrower independent check in `functional-intervention.json` found zero
changes among eight executed-action/materialized-provenance comparisons.** In
clean runs, candidate and FIFO resolve the same public source order; no failure
pressure or repeated inspection activates the added mechanism. Their N4 tool
and recorded control-operation counts also match in every world. This is a
useful null and does not satisfy a claim that coordination changed useful work.
The independent check changes neither the mechanism nor collected records.

A separate tokenizer-only check used the existing accepted Qwen2.5-Coder-3B
revision and verified tokenizer file hashes. Across 166 retained prompts and a
bounded public-error-feedback variant of each (332 tokenization operations),
the largest prompt was **930 tokens**, or **1,186 with 256 reserved completion
tokens**, below the 2,048-token limit. No weights or GPU inference were used.
Actual irrelevant-branch first-prompt differences from relevant ranged from
-130 to +46 tokens; matching was approximate, not exact. Details and limitations
are in `context-fit-config.json` and `context-fit.json`.

Next gate: retain this clean-run null, diagnose whether existing feedback/reuse
paths change actual work under separately declared counterexamples and development
behavior, and run authorized actionability diagnostics before any larger
collaboration collection. Scripted success and tokenizer fit cannot substitute
for an executed learned-policy experiment.
